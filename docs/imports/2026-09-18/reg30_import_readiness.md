## Changes made to import_ccr.py (each one, one line, with the reason)
1. `CORPUS_REGS["30"] = "30"` — registers Reg 30 so other regs' citations to it (and its own citations to Reg 3/7/22/26) resolve.
2. `REG_META["30"] = {...}` — standard state/CDPHE-APCD metadata, `root_citation`/`root_title` per the title page.
3. `SOB_PART_CONFIG["30"] = {"letter": "C", "top_family": "roman_seq", "top_opener_re": "Adopted:?\s"}` — Part C is a plain roman-numeral statement-of-basis sequence (I., II., III.), same family/opener as Reg 2's Part C.
4. `TABLE_CAPTION_EXTRA_RE["30"]` — reuses Reg 8's period-separated caption pattern (`Table 1. <text>`) for the one inline-captioned table (chromium fume-suppressant table under III.B.4.d.). Reg 30's other two captioned tables ("Table 1" / "Table 2", engine/turbine CO limits) are bare-digit captions already handled by the existing general `TABLE_CAPTION_RE` — no config needed for those.
5. `UNCAPTIONED_TABLES["30"]` — two entries pinning Appendix A's (CAS/chemical/date) and Appendix B's (chronic health-protective benchmarks) tables to their own appendix row ids, since neither is captioned "Table N" at all.
6. Added an optional `to_end: True` flag to the `UNCAPTIONED_TABLES` entry format (and a new shared helper `_swap_uncaptioned_table`, refactored out of the item branch and reused by the appendix branch): the default "run to the next blank line" cut (correct for Reg 8's tables, which have no blank lines inside their own flattened dump) stops too early for Reg 30's Appendix A/B dumps, which DO have blank lines inside them (wrapped table cells, each followed by pdftotext's usual paragraph gap). `to_end` instead runs the replacement to the end of the provision's own lines, which is exactly the whole table in both cases. No-op for Reg 8 (its entries don't set the flag).
7. Extended the appendix-heading regex to accept an optional colon (`Appendix A: <title>` — Reg 30's own style, "Appendix A: Priority Toxic Air Contaminants" / "Appendix B: Chronic Health-Protective Benchmarks..."). Every other regulation prints `Appendix <L> <title>` (no colon) or bare `APPENDIX <L>`, so the optional `:?` is a no-op for them.
8. Fixed a latent bug the colon-heading case exposed: when an Appendix's title wraps onto the very next physical line with no blank in between (Reg 30's Appendix B: "...for Priority Toxic Air\nContaminants"), the wrapped line was folded into the row's `title` AND left in `own_lines`, so it also reappeared as a stray `<p>Contaminants</p>` first paragraph in the row's body. Now the marker records exactly which physical lines it consumed into the heading (`heading_extra_lines`), and the appendix-building code drops that exact prefix from the body lines. Deliberately scoped to only the "same-line, no blank" continuation path — Reg 1's own `no_parts` fallback (title separated from its "APPENDIX A" marker by a blank line) is untouched, and its output stays byte-identical.
9. Extended the appendix-closing rule in `scan_markers`: previously an open appendix would only be closed early by the next statement-of-basis top-level entry for a SECTION-scoped SOB (Reg 1). Reg 30's Appendix A/B are physically printed inside Part C (a PART-scoped SOB) between its dated entries, so without this fix Appendix A would have swallowed SOB entries II and III (and Appendix B) entirely. The fix generalizes the same closing check to a part-scoped SOB whose own part is the one currently open — a no-op for every other regulation, none of which prints an appendix inside its own SOB part (confirmed by the byte-identical Reg 1/2/26 baselines).
10. `KNOWN_LABEL_FIXES["30"]` — one entry for the "III.D.1. g.(iv)" stray-space typo (see below).
11. Extended `REG_NUM_RE`/`BARE_REG_RE` to accept the abbreviated "No."/"No" in addition to "Number" ("Regulation No. 3", "Regulation No. 27" — Part C's Basis narrative, line 4863-4864). No baseline regulation (1/2/26) ever prints "Regulation No.", so this is a no-op for them; it correctly links "Regulation No. 3" to the in-corpus Reg 3 and buckets "Regulation No. 27" as `other_reg` (Reg 27 is deliberately not in the corpus) instead of both falling into `unparseable`.
12. Fixed the link/span text for the "Regulation Number N" match to use the exact matched substring instead of a hardcoded "Regulation Number {num}" string — needed so "Regulation No. 3" doesn't render (or get bucket-counted) as "Regulation Number 3" after change #11; a no-op for every existing citation, which always literally printed "Regulation Number".

## Anything the summarizer should be warned about for this regulation
- **PTAC vs TAC**: "Toxic air contaminant" (TAC) is the general term; "Priority Toxic Air Contaminant" (PTAC) is the narrower, Commission-designated subset this regulation actually controls (currently five: Benzene, Chromium Compounds/Hexavalent, Ethylene Oxide, Formaldehyde, Hydrogen Sulfide, per Appendix A). Don't conflate the two in a summary.
- **Health-based values**: Appendix B's "chronic health-protective benchmark" values are, per the regulation's own text, still proposed/pending General Assembly approval as of the September 19, 2025 amendment (see `sec-30-B-II-A` and `sec-30-C-II`'s Basis) — a summary should not present them as final/self-executing without checking the in-force text's own qualifying language.
- **Reporting deadlines**: numerous hard dates threaded through Part B (e.g. October 31, 2027 one-time cost-effectiveness analysis under III.F.2; various "Beginning [date], or upon commencement of operation if such date is after June 14, 2026" phasing clauses) — these are compliance-critical and should be preserved verbatim, not paraphrased into relative time.
- **"Division" = APCD**: as with every AQCC regulation, "Division" means the Air Pollution Control Division (CDPHE-APCD), not a division of the regulated entity.
- **HB22-1244 context**: Part C's Basis sections explain that this regulation implements House Bill 22-1244 (§ 25-7-109.5, C.R.S.) — only surface this framing if the summarized text itself references it (it does, in `sec-30-C-I` and `sec-30-C-APPENDIX-A`'s enclosing entry), not as inferred background.
- **Tables as data, not prose**: Appendix A/B and the two chromium/engine/turbine tables carry compliance-critical numeric thresholds (CO emission limits, surface-tension limits, health-protective benchmark concentrations) — a text summary should point to "see table" rather than attempt to restate every cell.
- **Acronyms likely to be mis-expanded**: HQ (Hazard Quotient), IUR (Inhalation Unit Risk), RfC (Reference Concentration), PTAC/TAC (see above), HEPA, AIRS ID (a specific facility identifier, not a general term) — all defined in Part A's I.A. Definitions or inline in Part B; a summarizer should use the regulation's own definitions rather than a generic expansion.
