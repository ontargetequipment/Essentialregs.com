# Reg 6 — import readiness report

## Verdict: READY WITH NOTES

All nine quality gates pass. The notes are (a) the parser needed one genuinely new, config-gated capability for Reg 6's Part A (a part with no labeled sections at all — see "Changes made"), (b) three cosmetic carry-overs of existing parser behaviour (editor's-notes history block appended to the last row, one uncaptioned SOB timeline table left as garbled text, a page-seam paragraph join), and (c) Reg 6 contains NO citations to OOOOa/OOOOb/OOOOc (only the un-suffixed "Subpart OOOO"), so the corpus-link path for those subparts could not be exercised on this regulation.

## Changes made to import_ccr.py (each one, one line, with the reason)

1. `CORPUS_REGS["6"] = "6"` — so Reg 6 links resolve from/to the corpus (Reg 3 and Reg 7 links from Reg 6 confirmed, 9 anchors).
2. `REG_META["6"]` — state / CDPHE-APCD / aqcc-regulations URL / "Code of Colorado Regulations · Regulation Number 6" / "STANDARDS OF PERFORMANCE FOR NEW STATIONARY SOURCES 5 CCR 1001-8" (Reg 3/26 conventions).
3. `SOB_PART_CONFIG["6"] = {letter "A", roman_seq, opener ^Adopted:?\s, inner_items False}` — Part A's own tail is the Part A statements of basis (the colon after "Adopted" is inconsistent in print; inner "1./2./3." lists restart inside entries exactly like Reg 3 Part F, so each entry is one row).
4. NEW config dict `FLAT_ENTRY_PART_CONFIG` (`"6": letter A, bare_part_headings True, sob_heading_re`) + helpers `_flat_entry_match`, `_flat_entry_title` and regexes `_FLAT_SUBPART_RE`, `_FLAT_APPENDIX_RE`, `_FLAT_TABLE_RE`, `_FLAT_TITLE_CUT_RE`, `FLAT_SUBPART_REF_RE`, `_FLAT_PRECEDING_PART_RE` — Reg 6's Part A has NO roman/upper/digit labels at all; without this the whole ~700-line incorporation-by-reference block (intro, both tables, 98 subparts, 16 federal appendices) was silently dropped (a part marker owns no text and nothing tokenized). Every printed entry becomes one row in printed order. Consulted only for regs in the dict.
5. `scan_markers`: bare-"PART X"-line headings (title taken from the next non-blank line, `skip_until` so the title line is not re-scanned), gated on `bare_part_headings`; a `flat_active` branch (runs only between the flat part's heading and its `sob_heading_re` line) that emits "entry" markers (INTRO on the part heading, TABLE-n on centered "TABLE n" captions, SUBPART-<code>, P<nn>-APP-<L>, SOB) and hands over to the existing SOB branch at the heading — Reg 6 prints "PART A" / "PART B" alone on the line; every other reg prints "PART X <title>".
6. `_consume_heading_continuation` split into `_heading_continuation_lines` (returns the list) + the original join — needed to know how many title lines to skip; identical output for existing callers.
7. `build_provisions`: new `type == "entry"` branch (id `sec-<reg>-<letter>-<suffix>`, parent = part root, kind "entry"; table rows inject the pdfplumber table then drop the raw pdftotext table lines up to the last row-key line, keeping footnotes as paragraphs; subpart/appendix titles = "Subpart Xx — <first sentence before the '40 CFR' citation>") and a matching `"entry"` render branch (table html first, then footnote paragraphs).
8. `find_body_start(lines, reg=None)`: also accepts a bare "PART A" line, only when `bare_part_headings` is set for `reg`; `parse_reg` passes `reg`. The default call is unchanged.
9. `link_citations` step 1: a "40 CFR Part 60, Subpart Xx" citation that is not a corpus reg (OOOOa/b/c still win) but IS one of this reg's SUBPART entry rows links to that row as a same-reg xref (Reg 6 adopts those subparts itself — 5× "Subpart Da", 4× "Subpart IIII", etc. that were in the `cfr` bucket now link; only genuinely un-adopted ones remain: Subpart Ce, Part 63 UUUUU, Part 62 G, Part 72). Gated on `FLAT_ENTRY_PART_CONFIG.get(reg)`.
10. `link_citations` new step 6: bare "Subpart(s) Xx[, Yy and Zz]" mentions link to the SUBPART entry rows (first code carries the keyword, later ones bare, unknown codes left plain; skipped when preceded by "Part <n≠60>", e.g. "40 CFR Part 75, Subparts A through H"). Gated the same way; 410 spans now target Part A entries.

Existing-regulation safety: `out/reg26_before.json` (ORIGINAL parser) and `out/reg26_after.json` (edited parser) are **byte-identical** (`cmp` clean); all 32 pre-existing tests still pass. `reg6.patch` dry-applies cleanly to `import_ccr.ORIGINAL.py` + `pipeline/test_import_ccr.py`.

## Anything the summarizer should be warned about for this regulation

- **Part A rows are adoption-by-reference records, not regulatory text.** Each `sec-6-A-SUBPART-<code>` row typically reads "<federal title>. 40 CFR Part 60, Subpart Xx (July 1, 2025)." — the substantive requirements live in the federal CFR, not in this row. A summary should say "Colorado adopts 40 CFR Part 60 Subpart Xx (as of July 1, 2025) by reference" and must not invent requirements. A handful carry Colorado-specific deviations that DO matter: Subpart A (see Part B for modifications), Cc and Cf (landfill 111(d) plan compliance schedule, revised §60.33f text), K (three paragraphs), MMa, GGG, VVV, WWW, DDDD (Colorado's CISWI state plan: divisions, compliance dates), and the Part 60/75 appendices ("Reserved" ones are placeholders).
- "Administrator" means the Colorado APCD throughout Part 60-adopted text EXCEPT the sections in Table 1 (`sec-6-A-TABLE-1`), and means EPA for Part 75 except mercury MRR (Part B Section VIII) — stated in `sec-6-A-INTRO`.
- Every Part A entry carries a "(July 1, 2025)" (some 2023) CFR edition date — this is the incorporated CFR edition, not an effective/compliance date.
- The 32 Part A SOB rows (`sec-6-A-I`…`XXXII`) and the 8 Part B SOB rows (`sec-6-B-IX-A`…`H`) are rulemaking history/statement-of-basis narrative (dated 1996–2025), not requirements; several are long (up to 3,500 words). They cite many Federal Register actions, court cases (CAMR vacatur, DNREC v. EPA), and "Regulation Number 1/3/7/8".
- Part B Section VIII (`sec-6-B-VIII-*`, ~150 rows) is Colorado's **state-only mercury program for coal-fired EGUs** (Hg Budget Units, Hg emission standards in lb/TBtu, Low Emitter provisions, BAMCT, unit-by-unit lists such as Rawhide Unit 101 / Pawnee Unit 1 / Comanche Unit 3 / Craig Unit 3), created after the federal CAMR was vacated; it interacts with 40 CFR Part 63 Subpart UUUUU (MATS) — the summarizer should not conflate the two.
- Acronyms likely to be mis-expanded: NSPS (New Source Performance Standards), MWC (municipal waste combustor), CISWI (commercial/industrial solid waste incineration), OSWI (other solid waste incineration), SSI (sewage sludge incinerator), HMIWI (hospital/medical/infectious waste incinerator), ICE (internal combustion engine — Part B I.C relocation rule), EGU (electric generating unit), CAMR (Clean Air Mercury Rule), MATS/UUUUU (Mercury and Air Toxics Standards), BAMCT (Best Available Mercury Control Technology), MRR (monitoring, recordkeeping and reporting), Hg Budget Unit, CEMS/COMS, SOCMI, VOL (volatile organic liquid), NMOC, "111(d) plan" (CAA §111(d) state plan for existing sources — Subparts Cb/Cc/Cf/DDDD/FFFF/HHHH/MMMM are emission GUIDELINES for existing sources, not NSPS).
- Part B Sections II–VII contain numeric emission limits and equations rendered as plain text (e.g. "PE = 0.5 (FI)0.26" is PE = 0.5·FI^0.26; particulate limits in lbs/MMBtu; opacity 20%; biomedical waste incinerator temperatures 1800°F); the summarizer should quote them, not recompute them.
- Tables: `sec-6-A-TABLE-1`/`-2` are HTML tables; the MWC timeline in `sec-6-A-I` is a garbled text run — treat with caution.
